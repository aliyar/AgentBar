# Development notes

How the repository is put together, and the things that are easy to get wrong.

## Layout

```
AgentBar/
├── project.yml              xcodegen spec — the source of truth for the Xcode project
├── Makefile                 generate / build / run / test / screenshots / release
├── AgentBar/                the app target (SwiftUI + AppKit)
│   ├── App/                 @main, AppDelegate, AppDependencies (composition root)
│   ├── Features/            StatusItem, Overview (popover), Usage, Conversations, Settings, Updates
│   ├── Support/             Log, AppActivation, small extensions
│   └── Resources/           Assets.xcassets (AppIcon is generated by scripts/make-icon.swift)
├── AgentBarTests/           app-layer tests (hosted in the app) and the screenshot harness
├── Packages/AgentBarKit/    everything that is not UI: models, readers, snapshot codec
├── Supporting/              Info.plist and entitlements, generated by xcodegen (gitignored)
├── scripts/                 release.sh, sign-app.sh, install-local.sh, upload-r2.sh, make-icon.swift
├── site/                    the landing page (Next.js static export), see below
├── docs/                    this file, RELEASING.md, screenshots/
└── render.yaml              Render static site: root `site`, publish `out`
```

The Xcode project is **generated**: edit `project.yml`, then `make generate`. Never edit the
`.xcodeproj` by hand; it is not committed.

## Commands

| Command | What it does |
|---|---|
| `make run` | generate the project, build Debug, relaunch the app |
| `make test` | `swift test` on AgentBarKit (headless, seconds) + app tests through `xcodebuild` |
| `make test-kit` | only the package tests |
| `make screenshots` | render `docs/screenshots/*.png` from the real views (see "Screenshots") |
| `make icon` | regenerate the AppIcon set |
| `make install` | Release build, ad-hoc sign, install into /Applications, relaunch |
| `make logs` | `log stream` for subsystem `com.greatpixels.AgentBar` |
| `make site` / `make site-build` | landing page dev server / static export into `site/out` |
| `make release VERSION=x.y.z` | the release pipeline (docs/RELEASING.md) |

## Architecture

```
AgentBar.app  (com.greatpixels.AgentBar, LSUIElement, not sandboxed, Developer ID)
├── AgentBarKit (SPM, no AppKit in the models)
│   ├── Models: Agent, UsageLimit, Conversation, Snapshot (Codable)
│   ├── Readers: ClaudeReader, CodexReader  (pure functions over Data/String, tested)
│   ├── Process: owning application, parent pid, isRunning   (sysctl / kill(0))
│   └── SnapshotStore: writes/reads Snapshot in the App Group container
├── App
│   ├── AgentsModel: refresh loop, publishes Snapshot
│   ├── StatusItem: gauge title "78%" or symbol, popover on click
│   ├── Overview (popover and Dock window share it; Usage and Conversations are its sections), Settings, UpdateController (Sparkle 2)
└── AgentBarWidget.appex  (WidgetKit, sandboxed, App Group) — decodes the snapshot only
```

Only the app skeleton exists today; the rest lands milestone by milestone.

- **Swift 6, main actor by default.** `SWIFT_DEFAULT_ACTOR_ISOLATION: MainActor` is on for the
  app target, so every type is main-actor unless marked `nonisolated`. Parsers and anything
  that runs off the main actor are `nonisolated`. Member import visibility is on too: a file
  that uses `Logger` must `import OSLog` itself.
- **Composition root.** `AppDependencies` builds every long-lived object and wires the
  callbacks between them; nothing reaches for a singleton except `AppDependencies.shared`.
- **Tests never start the machinery.** `ProcessInfo.isRunningTests` gates the refresh loop and
  the updater in `AppDelegate`/`UpdateController`.

## Not sandboxed

The whole point of the app is reading `~/.claude` and `~/.codex`. A sandboxed app cannot
(the home-relative read-only entitlement is silently ignored, measured 2 Sep 2026), so the app
ships with `com.apple.security.app-sandbox: false`, Developer ID signed and notarized, outside
the App Store. `HomeDirectory` in AgentBarKit still resolves the home through `getpwuid`: it
costs nothing and survives a future sandbox experiment.

The WidgetKit extension *is* sandboxed (app extensions must be). It never reads the agents'
folders: the app writes one small JSON snapshot into the App Group container and reloads the
widget timelines; the widget only decodes it. The App Group id for a Developer ID app is the
Team-ID-prefixed form (`RCQFGHVGQJ.com.greatpixels.AgentBar`), not `group.…`: Sequoia checks
`group.` identifiers against a provisioning profile and prompts otherwise.

## Signing

Debug builds are signed automatically with the development team. Release builds are built
with `CODE_SIGNING_ALLOWED=NO` and then signed by `scripts/sign-app.sh`: Sparkle's XPC
services, `Autoupdate`, `Updater.app` and the framework individually, then the app with its
entitlements — never `--deep`, which would overwrite the nested signatures. With a Developer ID
identity the app gets the hardened runtime and a secure timestamp (both required for
notarization); ad-hoc builds get neither, because an ad-hoc signature has no Team ID and the
hardened runtime's library validation would then refuse the embedded Sparkle.

## In-app updates (Sparkle 2)

The feed is `https://agentbar.greatpixels.com/appcast.xml` (`SUFeedURL` in `project.yml`);
the zips are on the download host, never on GitHub, so the repository can stay private.
`SUPublicEDKey` is empty until the key pair exists; `UpdateController.start()` refuses to start
without it, so a development build simply has updates off. The key lives in the login Keychain
under account **`agentbar`** — always pass `--account agentbar` to `generate_keys` and
`sign_update`, the same Keychain holds the sibling apps' keys. Back the private key up once
(`generate_keys --account agentbar -x <file>`); losing it strands every installed copy.

To test against a local feed: `defaults write com.greatpixels.AgentBar UpdateFeedURL <url>`.
An unsandboxed app needs neither `SUEnableInstallerLauncherService` nor mach-lookup exceptions.

## The agents' files

The formats are **undocumented and the agents' to change**. Every field is optional on the way
in; the parsers degrade to "nothing reported", never crash. Pin them with tests against real
samples, dated in the test names.

- **Claude limits**: `~/.claude/cache/usage.json` — one ~2 KB file Claude Code keeps current on
  its own. `limits[]` carries `session`, `weekly_all` and `weekly_scoped` (whose
  `scope.model.display_name` names the per-model row); `five_hour`/`seven_day` are the
  fallback. **`percent`/`utilization` is what has been *used*** — show it as written, as a bar
  that fills. Never invert to "left".
- **Claude conversations**: `~/.claude/sessions/<pid>.json` — one file per running session, with
  the name Claude Code gave it and `status: "busy"`. Files outlive their process: check the pid
  with `kill(pid, 0)`.
- **Codex limits**: no usage file of its own — they ride in the session transcript's last
  `token_count` event (`payload.rate_limits.primary.{used_percent, window_minutes, resets_at}`,
  the reset a unix timestamp). The newest rollout is found by walking `sessions/YYYY/MM/DD`
  (never by listing thousands of files) and only its last 512 KB is read. Codex only writes while
  it runs, so a window whose `resets_at` is in the past is history: draw a dash, not the number.
- **Context percentage** only when the limit is known (`[1m]` marker or >200K tokens); otherwise
  show tokens. There is no reliable place the limit is written.
- **Walking up the process tree** to the owning terminal or editor: stop at the first `.regular`
  app, not the first process with a bundle id — Electron helpers have bundle ids and no windows.
- **Cost is not shown.** Claude Code writes a `totalCostUSD` it computed itself; Codex writes
  none and its prices are in no public table. A figure for one and a blank for the other reads
  as a bug.

## Screenshots

`screencapture` is not available to an agent, so `make screenshots` renders the README images
from the real SwiftUI views: `AgentBarTests/ScreenshotTests.swift` hosts each view in an
offscreen window and writes 2x PNGs into `docs/screenshots/`. `xcodebuild` does not forward
environment variables to hosted tests, so the Makefile hands the output directory over through
`build/screenshot-dir`. The site imports the images it needs from `docs/screenshots/` at build
time rather than keeping copies.

## Site

`site/` is a Next.js app with `output: 'export'`: every page is prerendered to static HTML
(metadata, sitemap, robots, Open Graph) and deploys as a Render static site — root directory
`site`, build `npm ci && npm run build`, publish `out`, domain `agentbar.greatpixels.com`.
`render.yaml` carries a build filter on `site/**` so app commits do not republish the site.
`site/app/release.ts` is the one place the site states the version and the download link;
`scripts/release.sh` rewrites it. The appcast is `site/public/appcast.xml`.
